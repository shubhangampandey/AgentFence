# Evaluation methodology

Security tests use Vitest, Supertest, real PostgreSQL, and real OPA, with unique synthetic workspaces. Only explicit OPA outage/malformed-response cases mock the authorization transport; they assert fail-closed behavior. SDK tests isolate the transport to inspect retry/error handling. Tests include all mandatory acceptance scenarios A–J and further concurrency, self-review, expiry, stale resource, revoked credentials/grants, CSRF, schema allowlist, role matrix, scoped collection, and audit-chain checks.

The Security Lab runs bounded reproducible experiments in a newly seeded isolated workspace. A lab result includes expected/actual outcomes and gateway evidence references. Its administrative-role check evaluates the permission matrix; the automated Supertest suite separately tests actual route enforcement. The Lab does not simulate arbitrary external attacker infrastructure or constitute an independent security certification.

Playwright runs Chromium at desktop and iPhone-sized widths. It checks public pages, session login, preview without execution, successful lookup, denied export, pending payment, a separate human review, audit verification, command palette, modal Escape behavior, major navigation pages, console errors, and horizontal overflow. Screenshots are captured from actual runs. This is focused regression coverage, not a full WCAG audit or exhaustive browser compatibility matrix.

`pnpm benchmark` seeds a distinct workspace, warms each case once, then measures wall-clock durations with `performance.now`. It records actual CPU/OS/Node/PostgreSQL details, sample sizes, p50/p95/p99, errors, and case iterations per second. Cases include HTTP policy evaluation, permitted/denied/approval-required/invalid gateway requests, transactional audit append, full-chain verification, and batches of five concurrent reads. The concurrent throughput unit is batches/second; multiply only when comparing request counts explicitly. The workspace lock intentionally serializes same-workspace work.

Results include local HTTP and database round trips, startup effects outside the warm-up, competing development processes, and a growing audit chain. They do not establish peak throughput, realistic enterprise workloads, multi-host latency, production durability, or adversarial resilience. Small-sample tail percentiles are descriptive only. Benchmark errors must be inspected, never hidden. The frontend's trace summaries are historical measurements, not this controlled benchmark.
